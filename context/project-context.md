# project-context.md

## 프로젝트 배경

이 프로젝트는 복정고 한국사 교사 찰리쌤이 한국사 수업에서 사용할 인터랙티브 웹게임을 만들기 위한 작업 공간이다.

교사가 혼자 모든 코드를 직접 짜는 방식이 아니라, Claude Code, Codex 같은 AI 도구와 협업하여 빠르게 만들고 검토하는 방식을 사용한다.

## 교육 철학

핵심 철학은 "Doing History"이다.

학생은 역사 지식을 외우는 데서 멈추지 않고, 역사 속 상황에 들어가 선택하고 판단해야 한다.

좋은 게임은 학생에게 이렇게 묻는다.

- 내가 그 시대 사람이라면 무엇을 선택했을까?
- 그 선택은 어떤 결과를 만들었을까?
- 당시 사람들은 왜 그렇게 판단했을까?
- 지금의 기준으로만 보면 놓치는 것은 무엇일까?

## 수업 활용 방식

- 한 게임은 15~25분 안에 끝나는 것을 목표로 한다.
- 태블릿 브라우저에서 바로 실행할 수 있어야 한다.
- 별도 설치나 로그인 없이 접속만으로 시작해야 한다.
- 수업 중 개인 활동, 모둠 활동, 정리 활동으로 사용할 수 있다.
- 결과 공유는 텍스트 복사 버튼 `navigator.clipboard.writeText()`으로 통일한다.
- PNG 저장은 기본 제공하지 않는다.
- 필요하면 학생 결과나 생각을 패들렛 같은 외부 도구로 공유할 수 있다.

## 배포 환경

- GitHub 조직: `gtmc-history`
- 배포 방식: GitHub Pages
- 허브 페이지: `https://gtmc-history.github.io`
- 허브 파일: 루트 `index.html`
- 기본 게임 URL 형식: `https://gtmc-history.github.io/games/폴더명/`
- 게임 위치: `games/게임폴더명/index.html`

새 게임을 배포할 때는 허브 페이지에도 게임 카드를 추가한다.

서버를 따로 운영하지 않는다. 데이터베이스도 사용하지 않는다.

## 블로그 연계

블로그 `hischarlie.tistory.com`에는 교사용과 학생용 안내를 나누어 제공한다.

- 교사용: iframe 미리보기와 전체화면 링크를 함께 안내한다.
- 학생용: GitHub Pages 직접 링크를 안내한다.

## 기술 원칙

- HTML, CSS, JavaScript 중심으로 만든다.
- GitHub Pages에서 정적 파일로 실행되게 만든다.
- GA4 측정 ID `G-G350VXSFGE`를 모든 게임에 넣는다.
- 어려운 역사 용어를 위한 툴팁 시스템을 넣는다.
- 외부 AI 연동이 필요한 게임은 Google Apps Script 프록시를 경유한다.
- API 키를 HTML, JavaScript, GitHub 저장소에 직접 노출하지 않는다.
- 외부 연결이 끊겨도 게임 자체는 완전히 작동해야 한다.
- Gemini API 사용 시 `thinkingConfig: { thinkingBudget: 0 }` 설정을 반드시 사용한다.
- 학생 개인정보를 수집하지 않는다.
- 로그인 기능을 만들지 않는다.

## 역사 오류 검토

코딩 전 반드시 역사 오류 패턴을 검토한다.

자주 생기는 오류:

- 시대와 맞지 않는 물건이나 표현을 넣는 오류
- 사건의 순서를 잘못 놓는 오류
- 국가, 왕, 인물, 지역 이름을 혼동하는 오류
- 원인과 결과를 단순하게 바꾸는 오류
- 역사적 선택을 착한 쪽과 나쁜 쪽으로만 나누는 오류
- 당시 사람들이 알 수 없던 정보를 선택지에 넣는 오류
- `호족`은 고려 태조 시기에만 적합한 표현이다. 고려 전기 이후에는 사용하지 않는다.
- `향리`와 `일반 양인(백정)`을 혼용하지 않는다.

## 좋은 게임의 기준

좋은 한국사 웹게임은 다음 조건을 만족한다.

- 학생이 자신의 역할을 바로 이해한다.
- 선택에는 역사적 이유가 있다.
- 결과 화면에서 배울 점이 분명하다.
- 수업 시간 안에 끝낼 수 있다.
- 선생님이 설명을 덧붙이기 쉽다.
- 태블릿에서 편하게 조작할 수 있다.

설계 기준:

- 장면 최대 7개
- 선택지 최대 4개
- 카드 텍스트 80자 이내
- 설명 120자 이내
- 툴팁 40자 이내
